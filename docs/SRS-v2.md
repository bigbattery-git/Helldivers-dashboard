## 1. 목적과 범위

헬다이버즈2 한국 플레이어가 **지금 어디서 싸워야 하는지**를 한 화면에서 파악하게 한다. 은하 전쟁 현황, 주요 명령(MO), 뉴스, 통계 추이를 한국어로 모아 보여준다.

- 이 문서는 MVP(1차 출시) 범위를 정의한다. 구현은 P2 환경 구축 뒤 **P3 MVP 구현**에서 한다.
- 데이터 소스·DB·스케줄러는 ADR 0001~0004에서 정했고, 이 문서는 그 위에서 무엇을 보여줄지 정한다.

## 2. 사용자와 사용 장면

| 사용자 | 장면 | 필요한 것 |
| --- | --- | --- |
| 플레이어 (주 대상) | 게임 켜기 전·출격 사이에 휴대폰으로 확인 | MO 진행률·남은 시간, 지금 뜨거운 전선, 디펜스 남은 시간 |
| 커뮤니티 공유자 | 디스코드·카페에 링크 공유 | 링크 미리보기(OG 이미지·요약), 행성별 고유 URL |
| 포트폴리오 열람자 | 기술 스택·품질 확인 | 빠른 로딩, 출처 표기, 깔끔한 그래프 |

설계 기준: **모바일 우선**(폭 360px부터), 한국어 우선, 로그인 없음.

## 3. 화면 구성

| 경로 | 화면 | 주요 내용 | 관련 기능 |
| --- | --- | --- | --- |
| `/` | 홈 대시보드 | MO 카드, 활성 전선 목록, 디펜스 이벤트, 최신 뉴스 5건, 동접자 24시간 미니 그래프 | F-01, F-02, F-03, F-04 |
| `/planets/[index]` | 행성 상세 | 행성 현황, 해방률·플레이어 수 30일 추이. **전 행성(약 260개)** 에 URL을 두되 빌드 때 미리 만들지 않고 첫 요청 때 생성·캐시한다 | F-01, F-04 |
| `/news` | 뉴스 | 통합 뉴스 피드(종류 필터) | F-03 |
| `/stats` | 통계 | 동접자·MO 진행률·전선별 추이 그래프 | F-04 |
| `/about` | 소개 | 데이터 출처, 갱신 주기, 비공식 팬 사이트 고지 | F-05 |

공통 레이아웃: 상단에 마지막 갱신 시각과 데이터 상태(정상/지연/폴백), 하단에 출처·고지.

## 4. 기능 요구사항

우선순위: **M** = MVP 필수, **S** = MVP에 넣으면 좋음(일정 남으면), **L** = 이후.

### F-01 은하 전쟁 현황

| ID | 요구사항 | 우선 | 데이터 (ADR 0001) |
| --- | --- | --- | --- |
| F-01-1 | 활성 전선(캠페인이 걸린 행성) 목록: 한국어 행성명, 섹터, 적 진영, 해방률(또는 방어 진행률), 플레이어 수 | M | `Status.campaigns`, `planetStatus`, `WarInfo`, 정적 `planets.json`(ko) |
| F-01-2 | 목록 정렬: 기본은 **현재 MO 목표에 든 행성 먼저, 그다음 플레이어 수 순**. 해방률·진영 정렬도 고를 수 있다 | M | 위와 같음 + `v2/Assignment` 태스크의 대상 행성 |
| F-01-3 | 디펜스 이벤트: 대상 행성, 공격 진영, 진행률, 남은 시간 카운트다운 | M | `Status.planetEvents` |
| F-01-4 | 진영별 요약: 진영마다 활성 전선 수·투입 플레이어 수 합계 | M | `Status` 합산 |
| F-01-5 | 해방 추세: 최근 1시간 해방률 변화량(+/−) | M | DB 스냅샷 차분 |
| F-01-6 | 이대로면 예상 해방·실패 시각 | S | F-01-5 추세로 외삽 |
| F-01-7 | 은하 지도: 행성 좌표에 마커를 놓고, 해방·방어 상태는 행성 툴팁으로 보여준다(디자인 시스템). 공급선은 그리지 않는다 | M | `WarInfo` 좌표 |

해방률 정의: `1 − health / maxHealth` (인류 소유가 아닌 행성 기준). 디펜스 중인 행성은 이벤트 HP로 따로 계산한다. 디펜스 이벤트 실제 응답 형태는 E-04에서 확인한다.

### F-02 주요 명령(MO)

| ID | 요구사항 | 우선 | 데이터 (ADR 0001) |
| --- | --- | --- | --- |
| F-02-1 | MO 제목·브리핑 (한국어, 없으면 영어 원문) | M | `v2/Assignment` + `ko-KR` |
| F-02-2 | 태스크별 목표·진행률 (예: "행성 X 해방", "적 N명 처치") | M | `progress`, `tasks[].values` + 정적 태스크 해석 표 |
| F-02-3 | 남은 시간 카운트다운과 만료 시각(KST) | M | `expiresIn` + 응답 시각 |
| F-02-4 | 보상 (종류·수량) | M | `rewards[]` + 정적 보상 표 |
| F-02-5 | MO 진행률 추이 그래프 (MO 기간 전체) | S | DB 스냅샷 |
| F-02-6 | 동시에 여러 MO가 있으면 모두 표시 | M | `Assignment` 배열 |

태스크 문구는 API가 비어 있는 값을 주므로 정적 해석 표로 만든다(ADR 0001). 해석 못 한 태스크는 "알 수 없는 목표 (type N)"으로 표시하고 수집 로그에 남긴다.

## 5. 데이터 수집 요구사항

수집은 `POST /api/collect` 하나가 맡고, Supabase Cron이 15분마다 호출한다(ADR 0004).

| ID | 요구사항 |
| --- | --- |
| D-01 | 15분마다 수집: Arrowhead `Status`, `v2/Assignment`(ko-KR), `NewsFeed`(ko-KR), Steam 동접자, Steam 뉴스 API·RSS, X 새 글 |
| D-02 | 1시간마다 `Stats/war/{id}/summary`, 하루 1회 `WarID`·`WarInfo` |
| D-03 | 응답은 zod로 검증한다. 원본 실패나 검증 실패 시 해당 항목만 커뮤니티 API로 폴백한다 |
| D-04 | 스냅샷은 15분 슬롯 단위로 저장하고 `UNIQUE(대상, slot)`로 중복 호출에 멱등하게 한다 |
| D-05 | 소스별 성공/실패/폴백 여부를 수집 실행 기록 테이블에 남긴다 (F-05-1·F-05-2의 근거) |
| D-06 | 30일 지난 스냅샷은 pg_cron이 하루 1회 삭제한다. 뉴스·디스패치 항목은 삭제하지 않는다 |
| D-07 | 수집이 끝나면 `revalidateTag`로 화면 캐시를 갱신한다. 화면은 DB만 읽고 외부 API를 부르지 않는다 (SRS v1 N-01) |
| D-08 | 한 소스가 실패해도 다른 소스 수집은 계속한다 |

주요 테이블 (`prisma/schema.prisma`, 결정 근거는 [ADR 0005](adr/0005-db-schema.md)):

| 테이블 | 내용 | 보관 |
| --- | --- | --- |
| `war` | 현재 시즌 ID, 시작·종료 시각 | 상시 |
| `planet` | 행성 좌표·maxHealth(WarInfo)와 현재 owner·health·players·캠페인·공격 출발지·행성 효과·진행 중 이벤트 | 상시 (매 수집 갱신) |
| `planet_event` | 디펜스 이벤트 (행성, 진영, 시작·종료, HP) | 30일 |
| `planet_snapshot` | slot, 행성, owner, health, players, 이벤트 HP | 30일 |
| `major_order` | id, 제목·브리핑(+lang), 태스크·보상 원본, 만료, 진행 중 여부 | 상시 |
| `major_order_progress` | slot, MO, 태스크별 진행 값 | 30일 |
| `global_snapshot` | slot, Steam 동접자 | 30일 |
| `news_item` | 소스, 외부 ID, 패치노트 여부, 제목·본문(+lang), 게시 시각, URL | 상시 |
| `raw_payload` | 소스별 최신 원본 응답 1건 | 덮어쓰기 |
| `collection_run` | 실행 시각, 소스별 결과 | 30일 |

행성 이름·섹터·효과 설명, 태스크·보상 해석 표는 DB가 아니라 저장소의 정적 데이터로 둔다. 텍스트는 한 칸에 저장하고 `lang`(ko/en)으로 언어를 표시한다.

## 6. 비기능 요구사항

SRS v1 §7(N-01~N-05)을 그대로 따르고, 아래를 더한다.

| ID | 요구사항 |
| --- | --- |
| Q-01 | 성능: 홈 화면 모바일 LCP 2.5초 이하 (캐시된 상태 기준) |
| Q-02 | 캐시: 화면 데이터 `cacheLife` revalidate 900초, 수집 후 태그 무효화 |
| Q-03 | 접근성: 색만으로 진영·상태를 구분하지 않는다(아이콘·텍스트 병기), 키보드 탐색, 그래프에 수치 대체 텍스트 |
| Q-04 | 반응형: 360px~1440px에서 가로 스크롤 없음 |
| Q-05 | Vercel Hobby 한도 안에서 운영: 광고·유료 기능 없음(비상업), 월 함수 호출·ISR 쓰기 한도의 50% 이하 |
| Q-06 | 장애 내성: 한 소스가 멈춰도 화면은 마지막 데이터와 지연 배지로 계속 보인다 |
| Q-07 | 테스트: 응답 파서·해석 표(태스크·보상·마크업)·시간 환산에 단위 테스트 |

## 7. 범위 밖 (MVP 이후)

- 로그인, 즐겨찾기 행성, 개인화
- 푸시·디스코드 봇 알림 (MO 시작·디펜스 발생)
- 라이트 테마
- 한/영 전환 UI (텍스트는 한 칸 + lang으로 저장하므로, 만들려면 스키마와 호출량을 다시 검토한다. ADR 0005)
- 30일보다 긴 이력, 다운샘플링 보관
- Reddit, Discord, YouTube 소스 (ADR 0002에서 기각·보류)
- 광고 (Vercel Hobby 비상업 조건)

## 8. P3 MVP 구현 완료 기준 (제안)

- [ ] 홈 화면이 모바일 LCP 2.5초 이하다
- [ ] 소스 하나를 일부러 실패시켰을 때 폴백·지연 배지가 동작한다
- [ ] Production 배포 URL을 확보했다
