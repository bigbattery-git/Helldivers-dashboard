## 1. 문제

수집은 Supabase Cron이 매시 00·15·30·45분(UTC 15분 경계)에 돌리고, 끝나면 캐시 태그를 무효화하고 `/`·`/news`·`/stats`를 예열한다(PR #16). 서버 쪽 페이지는 수집 직후 새것이 된다.

하지만 이미 열려 있는 탭은 렌더 시각의 데이터에 고정된다. 브라우저에서 도는 것은 지연 배지의 1분 타이머뿐이라, 탭을 켜 두면 수치는 그대로이고 30분이 지나면 수집이 정상이어도 "데이터 지연" 배지가 뜬다. 최신 데이터를 보려면 새로고침해야 한다.

## 2. 요구사항

| ID | 내용 | 우선순위 |
| --- | --- | --- |
| A-01 | 열린 탭은 수집 슬롯 + 2분(매시 02·17·32·47분, 브라우저 시계 기준)마다 페이지 데이터를 다시 받는다. 전체 새로고침이 아니라 `router.refresh()`로 받아 스크롤·펼침 상태를 유지한다. 홈·뉴스·통계 모두 | M |
| A-02 | 탭이 숨겨져 있는 동안은 받지 않는다. 다시 보일 때 그사이 갱신 시각이 지났으면 바로 한 번 받는다 (함수 호출·대역폭 절약, Q-05) | M |
| A-03 | 갱신 뒤 LAST UPDATE 시각과 지연 배지가 새 수집 기준으로 바뀐다(F-05-1). 갱신해도 마지막 수집이 30분 넘게 지났으면 배지는 그대로 뜬다 | M |

## 3. 결정 (2026-10-29)

| 질문 | 결정 |
| --- | --- |
| 갱신 시각 | 슬롯 + 2분. 수집(약 10초) + 예열 대기 3초 + 렌더가 끝난 뒤이고, 브라우저 시계가 1분쯤 틀려도 새 데이터를 받는다 |
| 기준 시계 | 브라우저 시계의 UTC 15분 경계(cron과 같은 경계). 마지막 수집 시각에 맞추지 않는다 |
| 받았는데 아직 옛 데이터일 때 | 다시 시도하지 않고 다음 슬롯에 받는다. 수집이 실제로 늦거나 멈추면 지연 배지(30분)가 알려 준다 |
| 적용 위치 | 루트 레이아웃 하나에 둬서 모든 화면에 적용 |
| 문서 | 이 문서(SRS v6)와 CHECKLIST P4 "자동 갱신" 절. 현재 단계는 P4 유지 |
