# srs-sync

작업 결과를 프로젝트 문서에 반영한다. 문서는 한국어로 쓴다.

## 1. 완료 항목 확인

1. `docs/CHECKLIST.md`를 읽고 `현재 단계:` 줄과 미완료 항목(`- [ ]`)을 파악한다.
2. 이번 작업으로 끝난 항목마다 **실제 근거**를 확인한다: 파일이 존재하는지, 명령이 통과했는지, 동작을 직접 확인했는지.
   - 근거가 있는 항목만 `- [x]`로 바꾼다.
   - 일부만 된 항목은 체크하지 말고 줄 끝에 `— 진행 중: <남은 일>`을 붙인다.
   - 사용자 확인이 필요한 항목(`[사용자]`, 새 세션에서 확인 등)은 사용자가 확인했다고 말하기 전에는 체크하지 않는다.

## 2. 단계 전환

해당 단계의 **완료 기준** 항목이 모두 `- [x]`일 때만:

1. `현재 단계:` 줄을 다음 단계(P0 → P1 → P2 → 완료)로 바꾼다.
2. 사용자에게 단계가 바뀌었음을 알린다.

완료 기준이 하나라도 남아 있으면 단계를 바꾸지 않고, 무엇이 남았는지 보고한다.

## 3. SRS 상태표 갱신

`docs/SRS.md` §9 상태표에서 각 단계 행을 갱신한다.

- 상태: `대기` / `진행 예정` / `진행 중` / `완료`
- 진행률: 해당 단계 섹션의 체크된 항목 수 ÷ 전체 항목 수 (완료 기준 포함), 정수 %로 반올림
- 비고: 막힌 점이나 사용자 조치 대기 항목을 짧게

## 4. ADR 작성

기술 선택, 데이터 소스 채택/기각, 범위 변경처럼 되돌리기 비용이 있는 결정을 했을 때 작성한다.

1. `docs/adr/`의 가장 큰 번호 + 1로 `NNNN-<영문-kebab-slug>.md`를 만든다 (4자리, 0으로 채움).
2. `docs/adr/0000-template.md` 형식을 따른다.
3. 고려한 대안과 기각 사유를 반드시 적는다. 근거 자료는 `docs/research/` 문서나 출처 URL로 연결한다.
4. 기존 결정을 뒤집는 경우 새 ADR을 쓰고, 이전 ADR의 상태를 `대체됨 (NNNN)`으로 바꾼다.

## 5. 보고

갱신한 항목을 짧게 정리해 사용자에게 알린다: 새로 체크한 ID, 진행률 변화, 작성한 ADR, 남은 사용자 조치.
